## 2024-06-11 - React Polling Re-renders s Fetch API
**Learning:** `fetch().then(res => res.json())` vrací vždy novou referenci pole (i když jsou data identická z pohledu obsahu). Pokud tuto novou referenci bezmyšlenkovitě vložíme do React state pomocí polling intervalu (např. každých 5s), způsobíme masivní re-renderování celého stromu komponent každých 5s. Zvláště u velkých komponent jako `App.jsx` (1000+ řádků s hlubokým dom) to má razantní dopad na paměť a využití CPU i v naprostém idle režimu.
**Action:** Pro polling datových polí z API, které se nemusí změnit, je kritické před nastavením stavu provést porovnání obsahu (`JSON.stringify` nebo deep check) a v případě shody vrátit původní referenci (`return prev`).

## 2024-05-24 - DOM Traversal in Playwright evaluation context is slow
**Learning:** Calling `window.getComputedStyle` on every DOM node during full-page traversal inside Playwright's `page.evaluate()` is a massive performance bottleneck, especially on large, complex, and modern DOMs (like Single Page Applications) where many elements might be hidden via `display: none` or size constraints. Calling it on every element iteratively scales poorly.
**Action:** When extracting visible elements or texts, use `document.createTreeWalker`. Crucially, before executing `getComputedStyle`, first check `node.offsetWidth === 0 || node.offsetHeight === 0`. If true, skip the node immediately. In the case of element-based TreeWalkers, use `NodeFilter.FILTER_REJECT` to instantly skip traversing the entire hidden subtree, resulting in massive performance improvements (O(N) to O(Visible_N)).
