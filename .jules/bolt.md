## 2024-06-11 - React Polling Re-renders s Fetch API
**Learning:** `fetch().then(res => res.json())` vrací vždy novou referenci pole (i když jsou data identická z pohledu obsahu). Pokud tuto novou referenci bezmyšlenkovitě vložíme do React state pomocí polling intervalu (např. každých 5s), způsobíme masivní re-renderování celého stromu komponent každých 5s. Zvláště u velkých komponent jako `App.jsx` (1000+ řádků s hlubokým dom) to má razantní dopad na paměť a využití CPU i v naprostém idle režimu.
**Action:** Pro polling datových polí z API, které se nemusí změnit, je kritické před nastavením stavu provést porovnání obsahu (`JSON.stringify` nebo deep check) a v případě shody vrátit původní referenci (`return prev`).

## 2024-06-14 - Export velkých datových JSON struktur na frontendu
**Learning:** Použití konstrukce `"data:text/json;charset=utf-8," + encodeURIComponent(JSON.stringify(data))` pro stažení souboru funguje dobře pro malé objekty. U velkých objektů (v našem případě objekt `activeSession` může obsahovat desítky base64 stringů screenshotů - desítky MB) dochází při `encodeURIComponent` k masivnímu blokování hlavního vlákna prohlížeče i na stovky milisekund a zároveň může prohlížeč narazit na maximální povolenou délku data URI.
**Action:** Vždy, když je potřeba generovat a stahovat velký exportní soubor na straně klienta, musí se použít instancování `new Blob([data])` a následné vytvoření stahovacího odkazu pomocí rychlého `URL.createObjectURL(blob)`. Nezapomenout po stažení zavolat `URL.revokeObjectURL(url)` k uvolnění paměti.
